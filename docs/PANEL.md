# The panel (CEP extension)

The extension is a thin client: it renders the UI tree the host sends, runs the scripts the host sends and
forwards Premiere events. It knows no module and no business rule. Source: `src/premiere_deck/panel/`; it is
shipped inside the exe as data and installed by the host (section 4).

## 1. Files

```
panel/
  CSXS/manifest.xml     bundle com.softoblivion.premieredeck, version = host version (generated by the build)
  index.html            the display page (one file, inline <script> tags that load js/*.js)
  agent.html            the headless page (no UI, loads js/common.js + js/agent.js)
  css/panel.css         the panel's look in plain CSS; its token block is generated (section 3)
  icons.svg             the icon sprite: one <symbol id="i-<name>"> per icon (24 px grid, 1.75 px stroke, round
                        caps) and the glyph `glyph-pr`; nodes name an icon by `<name>` (`icon`, PROTOCOL.md 6.1) and
                        the display draws <svg><use href="#i-<name>"/></svg> after inlining the file at start
                        (XMLHttpRequest, else `cep.fs`; a `file:` page cannot reference an external sprite)
  fonts/                Sora-latin.woff2 (variable), GeistMono-Variable.woff2 and their licence files (section 3)
  js/CSInterface.js     Adobe's library (CEP 12 version), unmodified
  js/common.js          discovery (deck.json), WebSocket client with reconnect, message helpers, logging
  js/agent.js           script runner (evalScript wrapper, paging), event bindings, heartbeat, host autostart
  js/display.js         renderer of the UI tree (section 2): stage and scale, lanes, pinned row, tiles, action
                        sender, tooltip, results, menus, prompt popover, toast, theme
  host.jsx              ExtendScript loaded at startup: json2.js contents, __deckError, __deckBind helpers
  VERSION               host version string (generated)
  META-INF/             signature (generated by build/sign_panel.ps1; absent in a dev install)
  .debug                dev only: remote debugging ports (not shipped)
```

The 1.x files `glyph.svg` and `fonts/Unbounded-latin.woff2` are gone (the glyph is the symbol `glyph-pr`). The
sprite is a subset of the project's icon drawings plus `undo`; a test (`tests/panel/run.js`) checks that every
`icon = "..."` of the modules exists in it. Icon names the host uses: `folder` and `actions` (the tabs), `open-folder`, `sort`, `sync-all`, `sync-used`, `zip`,
`journal`, `undo`, `check`, `cross`, `info`, `warn`, `chevron`, `power` (start host), `open` (Open host), `pin`
(the pinned row's mark), `plus` (its edit slot), `scale` (the footer slider) and one icon per quick action
(`QUICK_ACTIONS.md` 1). Symbols added in 2.1 for the new quick actions (the modules use
exactly these names): `track-video-add`, `track-video-remove`, `track-audio-add`, `track-audio-remove`, `colour`,
`ratio-16-9`, `ratio-9-16`, `ratio-custom`, `export`, `ease-slow`, `ease-med`, `ease-fast`, `ease-linear`. A node
naming a symbol the sprite lacks is drawn without an icon (logged once).

Two extensions in one bundle (as the Premiere MCP bridge does on this machine):

| Extension id | Page | Lifecycle | Role in `PROTOCOL.md` |
|---|---|---|---|
| `com.softoblivion.premieredeck.agent` | `agent.html` | `<AutoVisible>false</AutoVisible>`, `<StartOn>` `com.adobe.csxs.events.ApplicationActivate` and `applicationActivate`, type `Custom` (invisible) | `agent` |
| `com.softoblivion.premieredeck.panel` | `index.html` | `Panel`, menu entry "Premiere Deck" under Window > Extensions, default size 360 x 640 (the stage, section 2), min 320 x 480; opened by the user only (never by the host, section 4) | `display` |

Manifest: `ExtensionManifest Version="7.0"`, host `PPRO` version `14.0` and up, `RequiredRuntime CSXS 9.0`,
CEF parameters `--allow-file-access-from-files` (no `--enable-nodejs`: the panel uses `window.cep.fs` and
`window.cep.process` only, which keeps the extension free of Node). The lifecycle values above were checked live
against the stray window at Premiere's start (5.1): the agent is never shown, so they stay.

## 2. Display renderer

The panel is one fixed stage of 360 x 640 CSS px (the "Lanes" layout): a top bar, the body with the selected tab,
a footer. Every titled tile group is one row ("lane") with its code at the left edge; the pinned row sits on top of
the first tab that has lanes.

- Keeps the last `ui` message and the last `theme`; renders sections and nodes per `PROTOCOL.md` 6.1 into the DOM;
  reconciles by node id so a focused `input` keeps its caret and a scrolled `list` keeps its position across
  re-renders.
- Stage: the stage is 360 px wide and at least 640 px high, centred when the panel is wider; with a taller panel the
  stage grows to the panel's height (the extra space is empty and stays below the tab's content, the notice slot and the undo row); a shorter
  or narrower panel scrolls the whole page. Nothing reflows with the panel width: every tile grid uses fixed tracks,
  so a short last row keeps the tile shape. The manifest's default size is 360 x 640, the minimum 320 x 480.
- Scale: the footer slider (80 to 150 %, steps of 5, a tick at 125 %) sets CSS `zoom` on the stage; zoom scales the
  layout box, so centring and the page scroll keep working. The value is stored in `localStorage` (`deck.scale`,
  per panel on this computer). Without a stored value the panel starts at 125 % when its `devicePixelRatio` is 1.25
  or more, else at 100 %; that first value is stored only once the slider moves. The scale is the panel's own: it
  sends nothing to the host.
- Frame: a top bar with the 24 px glyph, the tabs and the connection dot (mint when connected, amber while
  connecting; its tooltip is the tree's `status` text); the body shows the selected tab; the footer holds the
  version ("v" and the version number of `footer.text`, in mono; the panel's own `VERSION` while no host is
  connected), the scale slider and the small "Open host" pill (`footer.link`; disabled while no host is connected).
- Tabs: one per section of the tree, in the tree's order, drawn as one pill track with a sliding thumb (the
  section's `icon` and `title`). The selected tab is remembered in `localStorage` by section id; when it is not in
  the tree (or none is stored) the first section is selected. The panel knows no module, so the default tab is the
  host's first section (module `order`: Quick actions before Files). A section's `status` is accepted and not
  drawn.
- Lanes (`group` with `tiles` and a `title`): one row on a soft plate: the group's `short` at the left edge (34 px
  column, the `title` in its tooltip; without `short` the first four letters of the title, upper case) and the
  group's buttons and switches as tiles of 46 x 44 px (the icon over the code), six per row, 4 px apart. Other nodes
  of the group follow the row at full width. The lane's result line goes to the tab's notice slot
  (below). A lane has no caption, so `collapsible` does not apply to it.
- Notice slot: each tab that holds lanes, tile blocks or the pinned row has one slot of a fixed height (20 px,
  `--slot-h`) directly under the tab's content, inside the tab panel: on Actions under the last lane, on Files
  under the last group (the Offline group, or the tiles when there is none). In a taller panel it stays right under
  that content, beside the tiles, and the extra height is empty space below. A tab without tile groups has none.
  The slot is always in the tree, empty or filled, and always one line: it shows results only, never a question,
  and a result line takes the same room as an empty slot, so nothing moves a tile and the pointer stays on the
  tile it pressed. It holds the newest result line of the tab's lanes, pinned row and tile blocks, or nothing. A
  result line starts with the code of its lane in the `section` role ("TRKS · Removed V2"; "PIN ·" for the pinned
  row; no prefix for a block of row tiles, the Files tab). A result line wider than the slot is cut with an
  ellipsis; while it is cut, hovering the slot shows the tooltip card with the full text (the hint says "Click to
  read more." when the line has a `detail`). The first click on a line closes it and, when it has a `detail`, opens
  the detail as a small card above the slot, over the lanes; a click on the card, Esc or the next result of the
  same lane closes it. A slot with nothing to show has no tooltip. Lines of the groups that are not tile groups
  stay under their own items.
- Row tiles (`group` with `tiles` and no title, the Files tab): tiles of 165 x 46 px, two per row (the icon beside
  the code).
- Tiles: a tile is a wrapper (`data-tile` = node id, `data-zone` = `lane`, `row` or `pins`, `data-anchor` =
  `<zone>:<id>`) around its body button (`data-action`, `aria-label` = the full `label`, the tooltip) and the
  separate press targets drawn on it:
  - `switch` (SOLO, LOCK): the whole tile is the switch (`role="switch"`, `aria-checked`, `data-value` on the body);
    a lamp dot in the top right corner shows the state (mint while on, the icon in mint too). A click (not while
    `busy`, `disabled` or offline) flips the tile at once (`local.pending[id]`) and sends `action` with `value` = the
    new state; the next `ui` message clears every pending value, so the host's tree wins (a refused change comes
    back as the old value with an `action_result`, whose glow the tile shows for 2 s). Outside a tile group a switch
    is a row tile of the full width.
  - `button.menu`: the corner mark (a 6 px right triangle in the top right corner, clipped from a square with
    `clip-path: polygon()`, filled with the `swatch` colour of the current option when it has one, else with the
    ink colour) opens the menu; the mark has its own tooltip, the
    tile's label over "Current: <option label>."; the tile's own tooltip never repeats the value. A right click on
    the tile opens the menu as well.
  - `button.prompt`: the same corner mark (tooltip: the prompt's `label` over "Current: <value>.") opens a popover
    with one text field (starts with `value`, `placeholder`) and an "Apply" button; Enter or the button sends
    `action {id: prompt.id, value: <the text>}` and closes it; Esc or a click outside closes it without sending.
  - `button.auto`: the automation capsule, its own press target with its own tooltip (`label` over `hint`). On a row
    tile it is the AUTO zone at the right end (70 px, behind a hairline: the word AUTO and a capsule, mint while
    on); on a small tile a capsule in the top right corner. A press flips it at once and sends `action {id: auto.id,
    value: !value}`; the next tree is the truth. A busy or disabled tile blocks its body only: the capsule stays
    usable (offline it is disabled).
  - A press on the body sends the button's own `id`; with `confirm` it arms the tile first (the confirmation
    paragraph below).
- Pinned row (tree `pins`, `PROTOCOL.md` 6.1): drawn at the top of the first section that holds a lane, on an
  accent-rimmed plate with the pin mark at its edge: the referenced buttons and switches as small tiles (the same
  node: code, corner mark, capsule, state, action; an id with no node is skipped), an empty dashed slot per free
  place up to `max`, then the edit slot. A tree without `pins` draws five empty slots and the edit slot.
  - Outside edit mode a pinned tile runs its action like the tile in its lane; the result line of a press from the
    pinned row is shown in the notice slot with the prefix "PIN" (the display remembers where the press came from),
    and both copies morph. A pinned tile with `confirm` arms its own copy.
  - The edit slot ("+", tooltip "Edit pinned") turns edit mode on; it then shows a check ("Done") that turns it off,
    as do Esc, a tab switch and a lost host. In edit mode every pinned tile carries a cross in its corner that
    unpins it, the tiles below carry an accent rim (pinned ones a filled rim), and a press on a tile below pins it
    or unpins it. The pinned tiles answer only their cross, and the corner marks and capsules below act as part of
    their tile. A pin or unpin shows the new row at once (`local.pinsPending`) and sends `action {id: "panel.pin" |
    "panel.unpin", value: <action id>}`; the host's next tree is the truth. A press on a free tile while the row is
    full sends `panel.pin` without changing the row; the host answers with an `action_result` of id `panel.pins`,
    which the display shows as the pinned row's result line.
- Other groups: a caption (the `section` role, upper case) over the items; with `columns` 2 or 3 every run of
  consecutive `button` and `switch` nodes becomes a grid of that many columns; any other node takes the full width
  and ends the run; a run of one plain button is drawn full width. With `collapsible` the caption is a button
  (chevron; while collapsed the number of its buttons, switches and list rows; Enter / Space toggles it) and the
  state is remembered in `localStorage` per group `id`, expanded by default. Groups are keyed by `id` (a group
  without one by its title, a repeated title gets a counter), and items inside keep their id keys, so inserting or
  reordering groups never recreates a focused input.
- Tooltip: the display's own glass card, shown after 400 ms of hover or on keyboard focus (`:focus-visible` only),
  hidden on leave, on press, on scroll and on a scale change: the full `label` in bold and the `hint` line under it
  (`hint` alone for a node without a label). Never the code, the `meta` or a stored value; a stored value is the
  corner mark's own tooltip. Every tile has a card (its code is short, the name is in the card); a lane code has its
  group's title; an icon button its `label`; any other node a card when it has a `hint`. The card sizes to its text
  (at most 220 px), sits above the element and below it when there is no room above, and stays inside the stage's
  12 px gutter. No element carries a `title` attribute; the elements carry `data-tip`, `data-tip-label` and
  `data-tip-hint`.
- Floating cards (tooltip, menu, popover) live on the stage and are placed in stage pixels: an element's rectangle
  is divided by `stage width on screen / 360` (`stageRect`), which holds whether the engine reports zoomed
  rectangles or not. A menu or popover hangs from the right edge of the tile it was opened from (the pinned copy or
  the tile in its lane) and opens downwards when it fits. The cards are children of the stage, after the body, with
  a z-index above every lane, the pinned row and the toast; the body is a stacking context of its own, so no layer
  inside a lane can paint over a card.
- Results (`action_result`, `PROTOCOL.md` 6.6): the tile of that id (for a menu, prompt or auto id: the button that
  carries it) shows the outcome for 2 s (the icon rotates and scales out, a check with a mint glow for `ok`, a cross
  with a rose glow for `error`, the warn mark with an amber glow for `warn`, the check without glow for `neutral`
  spring in), then returns to its icon. The lane or tile block that holds the button shows a result line in the
  tab's notice slot, any other group keeps it under its items
  (icon, text, "HH:MM", in the outcome's colour; it survives re-renders); a button outside any group reports to
  its section's line at the foot of the tab. Notices close on a click (`CONVENTIONS` "Notices"): the line hides
  itself after 3 s (`ok`, `neutral`) or 10 s (`warn`, `error`), or with the next result of the group, or when the
  group leaves the tree; a click closes it; a line with `detail` has a chevron and the same click opens the detail
  (for a tile group as the card above the notice slot, else as its own line under the line), which has no timer and closes on its own click, on Esc, with the next result of the
  group or when the group leaves the tree.
- Menus: a small glass menu anchored to the tile (an option with a `swatch` shows a dot in that colour before its
  label; the display draws only `#rgb` / `#rrggbb` values; more than eight options take two columns) with the
  `options` (the current `value` marked with a check); a pick sends `action` with the menu `id` and the option's
  `value` and closes the menu; Esc or a click outside closes it without sending (the closing click does nothing
  else). While the host is away the corner mark opens nothing.
- Confirmation: a press on a tile with `confirm` (lane, pinned or Files row tile) arms the tile instead of sending.
  The face flips over (about 220 ms, a `transform: perspective() rotateX()` turn with an opacity fade) into two
  halves: a check on the left in the ok tone, a cross on the right in the neutral tone, inside the accent rim of
  the pressed state. The question is the tile's tooltip, shown at once without the hover delay and kept while the
  tile is armed (no bold "Confirm?" line, the question alone); a wide row tile also draws the question between the
  halves when it fits on one line, else only the two halves. A press on the check sends the button's own `id`
  (the result is reported where the press came from) and flips the tile back; the cross, a press anywhere else in
  the panel (which does nothing else), Esc, a tab change, or 4 s without a press flip it back without sending. A
  busy or disabled tile never arms. The flipped face is part of every tile that has `confirm` (not pressable
  while unarmed), so the flip back is animated too, and the icon and code return. Nothing else is drawn for it:
  no inline question, nothing in the notice slot, no tile moves. A `button` that is not a tile (a plain button
  in a column grid or a list row) keeps the inline question with two small pills, "Yes" and "No": in a column
  grid it spans the full row under the asking button's row; in a list row the row wraps so the question gets the
  full width. Never a native dialog.
- `busy` tiles show a spinner in the icon slot and an accent rim and ignore presses on the body; `disabled` tiles
  dim their body, corner mark and lamp; other `disabled` nodes are rendered at 45 % opacity with
  `pointer-events: none`.
- `variant` `icon`: a 28 px round button with the icon only; its `label` is the tooltip. A `text` with `chip` is a
  small status chip (a dot in the tone's colour, the text). A `row` that holds a text and an icon button is a header
  row: the text is drawn in the `title` role; a `text` that starts like a Windows path (`D:\`, `\\`) is drawn in
  mono. A `row` made only of buttons that is followed by nothing but groups sits last in the tab, right under the content and the notice slot (the
  Files undo row, below the Offline group); it moves up with the content in a taller panel.
- Lists: one compact row per entry: a dot in the row's tone (`warn`, `error`), the title in mono, the subtitle on
  the same line when it fits, the row's buttons as small pills.
- `progress`: a card with `label`, the bar, `detail` as one mono line under it and, with `cancel`, a "Stop" pill at
  the right that sends `action` with that id.
- Toasts (6.3): one line above the footer, fades after `ms`; a click closes it.
- Theme (`PROTOCOL.md` 6.5): the display sets `data-theme` on `<html>` to the name and remembers it in
  `localStorage`, so the next start draws the right theme before the host answers; before any theme is known it
  is `black`. A change runs the switch animation of section 3.
- Connection states: without a host connection and no tree yet, the body is the "Connecting to Host" screen: the
  glyph with a pulsing dot and the title "Connecting to Host"; after 15 s a soft second line "Start Premiere Deck
  on this computer" (a notice: a click closes it until the next connection; the start link is a control and
  stays); when `deck.json` names a `host_exe` that exists, a secondary link "Start Premiere Deck" (icon
  `power`) runs it (the link and the line appear together; in a development browser the exe cannot be checked, the
  click then answers "not found"; that answer line closes on a click). When a tree was shown and the host goes away,
  the last tree stays, dimmed and disabled, edit mode ends, and the connection dot turns amber. `welcome.update =
  restart_premiere` shows the one-line notice "Restart Premiere Pro to finish the Premiere Deck update" above the
  body (a click closes it for the life of the page; the header dot's tooltip still says it); `bye protocol` shows
  "Update Premiere Deck (host x)".
- Keyboard: Enter submits an `input` or the prompt popover; Esc closes the popover, a menu, an armed tile or a
  confirmation, the tooltip, an open result detail, then edit mode, where the host application passes the key to
  the panel (Premiere Pro keeps Escape for itself, so there the cross, a press elsewhere or the 4 s timeout
  disarm a tile). No other shortcuts (Premiere owns the keyboard).
- Text fields (the `input` node and the prompt popover's field) carry `spellcheck="false"` and `autocomplete="off"`:
  CEF would otherwise underline a size such as `1080x1350` as a misspelling.
- Outside Premiere (development): when the page is opened over `http(s)` and `window.__adobe_cep__` is missing
  (`DeckCommon.isDevBrowser()`), `deck.json` is fetched next to `index.html` at every connection attempt instead of
  being read through `window.cep.fs`. Inside Premiere (a `file:` page with the CEP bridge) this path never runs.
  Serve the panel folder with `python -m http.server` and run `tests/panel/live_server.py` (section 4.5).

## 3. Styling

The panel looks like the host window and follows the host's theme (`PROTOCOL.md` 6.5); it does not follow
Premiere's brightness setting (no `appSkinInfo`). The panel stays kit-free: nothing of the host's UI kit is imported
or copied as code; it shares the token VALUES only.

- Tokens: the block at the top of `css/panel.css` between the marker comments `/* BEGIN generated by
  build/gen_themes.py from ui/themes.json */` and `/* END generated */` is written by `build/gen_themes.py`: the
  Sora face, `--font-text` and `--font-mono` from `src/premiere_deck/ui/themes.json`, the type roles from the kit
  copy's `ui/vendor/liquid_ui/css/tokens.css` (below), and one rule per theme (`:root, :root[data-theme="black"]`
  and `:root[data-theme="sky"]`) with the same token names and values as the host (`--bg-top`, `--accent-ink`,
  `--ink-1` .. `--ink-4`, `--tint-sheet`, `--fill-2`, `--ok-ink`, `--line-soft` and the rest of the JSON). The block
  is never edited by hand; `build/build.ps1` runs the generator and `tests/test_themes.py` checks that the block
  matches the JSON and the kit's tokens. Everything below the block uses the tokens only (no colour literals; the
  exceptions are the white streak of the plates, `rgba(255, 255, 255, var(--btn-streak-*))`, and the sweep line of
  the theme switch).
- Type: the host's type scale, as the same custom properties: `--t-display` 20 px, `--t-title` 16, `--t-section` 11
  (upper case, tracked `--tr-section`), `--t-body` 13, `--t-label` 12.5, `--t-label-s` 11.5, `--t-caption` 11.5,
  `--t-mono` 12, `--t-mono-s` 11, with the weights `--w-*` and the tracking `--tr-*`. Every text below the generated
  block names a role (`font: var(--t-<role>)`, a weight token where a role needs more weight); no rule carries a
  pixel font size of its own (`tests/test_themes.py` and `tests/panel/run.js` fail on one). Mapping: tile codes
  `label-s` (strong weight), lane codes and captions `section`, result lines, chips, hints, notices and the toast
  `caption`, the footer version, the scale value, paths, times and counts `mono-s`, tabs, pills and the tooltip's
  name `label`, small pills and menu items `label-s`, the project name and screen titles `title`, other text `body`.
- Themes: Crystal Black (dark: near-black scene, crystal glass, cool white highlights) and Crystal Sky (light: pale
  sky-blue scene, white frosted glass, dark ink), both with the violet accent. Colour marks state only: mint ok and
  on, amber warn, rose error and the unpin cross, the accent for the primary action, the pinned row and edit mode.
  Body text keeps at least 4.5:1.
- Glass is CSS only: backdrop blur where CEF supports it (else the tint alone), a hairline rim, a top sheen.
- Fonts: Sora for all text (`fonts/Sora-latin.woff2`, the variable latin subset, the same file as the host's kit
  copy, with its OFL text); Geist Mono for the mono roles.
- Geometry (stage pixels, before the scale): top bar 48, footer 34, body padding 4 / 12 / 10; lanes 52 high (4 px
  padding, 5 px apart, the pinned row 11 px above the first lane); the notice slot 20 px high, 4 px under the
  last lane or group; the undo row 8 px under the slot; lane tiles 46 x 44, radius 12, a 18 px icon over
  the code, 5 px between; row tiles 165 x 46, radius 14, 6 px apart; the lamp 6 px; the corner mark a 6 px triangle
  in a 20 px press zone; the AUTO zone 70 px with a 22 x 13 capsule (9 px knob); the unpin cross 17 px. The Actions
  tab with its pinned row, eight lanes and the notice slot is 634 px high at 100 % (measured in the browser pane),
  so it fits the 640 px stage; a panel shorter than 634 px scrolls the page.
- Corner mark: the `::after` of the 20 px press zone is a 6 x 6 px square filled with `var(--mark, var(--ink-3))`
  and clipped with `clip-path: polygon(0 0, 100% 0, 100% 100%)` into the triangle. No border trick, radius or
  rotation: CEF 99 paints a rounded border box as a filled square.
- Scale slider focus: the default rectangular outline is off; keyboard focus draws a 2 px ring in `--focus-ring`
  around the round thumb.
- Tiles carry the pressable plate (streak, bevel, hairline, drop shadow) and the result morph; the press springs
  the plate (`scale(1.04, 0.95)`).
- Tooltip, menu and popover: glass cards (radius 12; the tooltip `--tint-sheet` with an arrow nub, at most 220 px;
  the menu, popover and detail card `--menu-tint` over a solid `--bg-mid` base, so they are opaque even where CEF
  draws no backdrop blur and nothing under a card shows through).
- Browser level: CEP 12 runs CEF 99 (Chromium 99, checked in the libcef.dll of the installed Adobe apps). The CSS
  therefore uses no `color-mix()`, no individual transform properties (`translate`, `rotate`, `scale`), no container
  queries and no `:has()`; tints and glows are overlay pseudo-elements with an opacity; a test greps for these.
  `zoom`, `max-content` and the `-webkit-appearance` range styling exist in Chromium 99.
- Theme switch: where `document.startViewTransition` exists, the host's sweep (`HOST_UI.md` 7: the new state
  revealed from top to bottom over 600 ms with a thin bright line). CEP's CEF may lack the View Transitions API;
  there the display crossfades instead: for 300 ms the root carries a class that puts CSS transitions on the
  colour, background and shadow properties, so the token values blend. Reduced motion: instant.
- Motion otherwise: 120 to 180 ms opacity and transform transitions; the result morph (2 s); the result line slides
  in; the unpin cross springs in; the looping animations are only the spinner, the indeterminate bar and the pulse
  of the connecting screen.

## 4. Install and update (host side, `host/panel_install.py`)

4.1 Target: `%APPDATA%\Adobe\CEP\extensions\com.softoblivion.premieredeck\` (per-user folder, no admin rights).
    The bundled panel is staged in `<data>\panel\` first (one copy per host version), then copied to the target
    with a temporary name and swapped (`<target>.new` -> rename old to `<target>.old` -> rename new -> delete
    old; a locked file leaves `.old` for the next run).
4.2 When: at every host start when `<target>\VERSION` differs from `__version__` or the folder is missing; after
    a self-update, this is how the panel updates. If Premiere is running, files are replaced anyway (CEF does not
    lock them) and the connected agent and every connected display get `reload` when only files changed (a display
    keeps its old files until its page reloads), or `welcome.update =
    restart_premiere` when the manifest changed (the installer compares the manifest hashes).
4.3 Signing: the build signs the staged panel with `ZXPSignCmd` and a self-signed certificate (`BUILD.md` 4);
    CEP accepts a self-signed signature as long as `META-INF` is intact, so a copied folder loads without
    `PlayerDebugMode`. Fallback: when the agent has not connected within 20 s of a Premiere start launched by the
    host, the host offers "Enable Premiere's extension debug mode" (one confirmation; writes `PlayerDebugMode=1`
    under `HKCU\Software\Adobe\CSXS.9` … `CSXS.12`) and records it in settings so it can be undone from Settings.
4.4 Uninstall (Settings > "Remove the panel from Premiere"): deletes the target folder and the registry values
    the host wrote.
4.5 Development: `powershell -NoProfile -File scripts\panel_dev.ps1` replaces the target with a directory
    junction to `src\premiere_deck\panel` and writes `.debug` (Chrome DevTools on `http://localhost:8098` for the
    panel, `8099` for the agent; not 8088, which the Premiere MCP bridge on this machine already uses);
    `-Remove` deletes the junction. By hand, the same is
    `cmd /c mklink /J "%APPDATA%\Adobe\CEP\extensions\com.softoblivion.premieredeck" "<repo>\src\premiere_deck\panel"`
    plus the `.debug` file of the source folder. `PlayerDebugMode` is already on on the development machine. The
    host skips installing when the target is a junction. Without a host, `tests\panel\live_server.py` (set
    `PYTHONPATH=src`) is a development host: it writes `deck.json` into the target (removed on a clean exit; a
    killed server leaves a stale one, which is harmless), serves the agent and the display (a sample tree with
    every node kind) and exposes `PremiereApi` on `http://127.0.0.1:47890/exec` (POST Python source; `api`,
    `server`, `state` in scope) and `/state`. Reload a page after a JS edit through DevTools (`Page.reload` on
    port 8098 / 8099) or by sending `reload`; restart Premiere after a manifest edit.
4.6 Opening the panel: the host never opens the visible panel (no `open_display`, `PROTOCOL.md` 3). The user opens
    it once from Window > Extensions > Premiere Deck; Premiere keeps it in the workspace and shows it at the next
    start. Until a display connects the host window stays in its waiting state with that hint (`HOST_UI.md` 3.2).
    The agent never calls `requestOpenExtension` either. "Check panel update" in the host window
    (`panel_check_update`, `BRIDGE_API.md` 2) runs the check of 4.2 on demand.

## 6. Implementation notes

- `common.js`: `DeckClient` per role. Reads `deck.json` at every connection attempt (so a new port or token is
  picked up), retries every 3 s for a minute, then every 15 s, and restarts the fast phase after a lost
  connection. Logs go to the host after the handshake; up to 50 are buffered while offline. `welcome.update =
  reload` is honoured at most once per 30 s (`sessionStorage`), so a host that keeps asking cannot loop the page.
- `agent.js`: one queue for host scripts and its own calls (`__deckBind`); the 2 s poll (`__deckState()`) runs only
  when the queue is empty. Wrapper: the script is the body of `function __deckBody()` inside an IIFE that declares
  `__args`, with `try` around the call (`PREMIERE_API.md` 7.7); the outcome is JSON-encoded by `__deckEncode` in
  ExtendScript and parsed back in the panel. On "EvalScript error." the agent asks `__deckCheckSyntax` for the
  message and line. A timed-out script keeps the slot until `evalScript` returns; its late outcome is logged, not
  sent. Results above 6 MB (UTF-8) are split into pages that never cut a surrogate pair. Binding events arrive as
  the CSXS event `com.softoblivion.premieredeck.event` and are coalesced per protocol event for 100 ms;
  `project.opened` / `project.closed` are always sent, other events only when subscribed. `deckAgent.recent` keeps
  the last 50 raw binding names for DevTools.
- `host.jsx` = `premiere/jsx/json2.js` (unmodified, checked by a test) + the `__deck*` helpers. The agent evaluates
  it with `$.evalFile` at every start, because the manifest's `ScriptPath` runs only when Premiere starts the
  extension and a reload after a file update would keep the old helpers in the shared engine.
- `display.js`: `Display(container, win)` takes the window it lives in (tests pass a stand-in). `renderTree(tree, local)` builds plain vnodes, `diff(old, new)` produces keyed operations
  (interactive nodes keyed by id, others by position and kind; properties applied after children so a select's
  value meets its options), `applyOps` patches the DOM; events are delegated through `data-*` attributes. While
  the host is away the last tree stays, dimmed and disabled. Local display state (selected tab, collapsed groups,
  result lines and their timers, open details, pending switch and capsule values, the pending pinned row, edit
  mode, the scale and the panel height, closed notices, open tooltip, menu or popover) lives outside the tree and is
  applied after the diff. The theme comes from
  the host (section 3); the panel does not read `appSkinInfo` or follow `ThemeColorChanged` (dropped in v1.1.0
  with the host-window look).
